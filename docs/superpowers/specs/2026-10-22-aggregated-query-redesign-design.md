# 河南专升本聚合查询与性能重构设计

**日期：** 2026-10-23

**状态：** 阶段性实施（多年份结果视图已完成）

**目标：** 在不丢失现有查询维度的前提下，把专业对照、考试科目、历年省控线、院校与招生计划整理成一次搜索即可阅读、筛选、预览和导出的聚合结果，并通过元数据和按需加载降低后续年份维护成本与首屏负担。

**本次落实：** metadata 驱动的 `selectedYears` / `focusYear` / `resultLayout`，原生年份多选弹窗，聚合卡片与表格双布局，以及预览和 CSV 共用的完整结果集。年份按钮直接显示已选范围，弹窗显示已选数量与当前基准年份；卡片和表格共用显式的详情视图状态，布局切换不会丢失已展开的院校明细。院校详情按学校身份合并为跨年份对比卡片，年份标记保留在计划记录上；表格不再为每个年份重复生成表头列，改为固定列和行内历年概览，表头在结果容器内冻结。`resultVisibilityRules` 把筛选条件映射为展示字段：建档立卡为“否”时，专项标签与专项计划记录一同隐藏。2027 fixture 演练覆盖从 metadata 加载到年份弹窗、表格、预览和导出的路径；其余数据采集与转换事项仍按本设计继续维护。

### 1.2 市面查询工具值得借鉴的部分

抽样查看的河南专升本查询平台通常提供：专业对照与科目、招生院校与专业、按院校或按专业查看招生计划、省控线、院校录取线、一分一段以及本科反向查询。其中“按考试科目与本科办学性质筛选”尤其符合本项目的数据基础。

本项目不照搬多入口门户结构，而采用一次查询后的聚合工作区。院校实际录取线和退役士兵考查当前没有足够源数据，暂不进入实现范围。2024–2026 一分一段表通过独立爬虫从官方来源批量下载，再由离线转换工具生成规范化 JSON 后接入；浏览器不直接解析 PDF。页面必须始终把控制分数称为“省控线”，不能写成“院校录取分数”；一分一段中的人数称为“累计人数/参考位次”，不能表述为唯一排名。

参考页面：

- 河南省专升本考试数据服务平台：<http://eazsb.cn/#/>
- 河南省教育厅、河南省教育考试院公开文件名称与转换口径见仓库 `README.md` 和 `转换说明.md`。

## 2. 产品原则

1. **一次查询、聚合展示。** 用户输入专科专业后，在同一结果中看到可报本科专业、公共课、专业基础课、三年省控线、三年院校与三年招生计划。
2. **保留现有维度。** 专业名称/代码、公共英语/专业英语、专业基础课及代码、公办/民办、普通/建档立卡、院校数、计划人数、院校全部明细都不得因重构丢失。
3. **事实与推导分开。** 原始文件字段先归一化；公共课等推导字段由 metadata 的规则生成，不在渲染代码中写专业名称正则。
4. **统一数据流水线。** 原始数据 → 归一化 → 聚合 → 筛选 → 排序 → 预览 → 导出。预览和导出使用同一结果对象与同一格式化器。
5. **渐进加载。** 先让搜索可用，再补当前年份聚合；历史大计划文件只在展开、预览或导出需要时加载。
6. **不伪造数据。** 缺失显示“—/未提供/该年未单列”，不把缺失当作 0，也不把回退院校信息当作正式招生计划人数。
7. **来源可追溯。** 官方原始 PDF、来源 URL、文件哈希、转换结果和异常报告必须能互相追溯；数据清洗不能覆盖或修改原始文件。

## 3. 聚合查询体验

### 3.1 页面结构

查询页从上到下固定为：

1. 搜索区：专科专业输入、候选提示、查询按钮。
2. 查询上下文：明确展示“当前按专科专业『某专业』查询”，并显示可报本科专业数量。
3. 筛选区：招生属性、考试科目、分数区间、招生规模四个小组。
4. 排序与操作区：metadata 驱动的排序、重置筛选、清除本地存储。
5. 聚合结果区：右上角固定“年份”和“布局”入口；本科专业摘要行/卡片与年份、院校逐级展开。
6. 导出预览区：默认折叠；打开时按需加载所需年度计划并分页展示。
7. 导出操作区：CSV 导出，后续可增加 XLSX 适配器。

数据分析和数据说明继续作为独立页签；ECharts 只在首次进入数据分析时加载。

### 3.2 搜索确认规则

- 输入时显示专科专业候选。
- 回车时若输入是精确专业名，直接查询。
- 否则优先采用键盘当前选中的候选；未选择时采用排序后的首个候选，并把完整专业名回填输入框。
- 查询上下文必须再次显示最终采用的专科专业名，避免用户误以为系统按模糊词汇汇总。
- 无候选时不自动猜测，显示友好提示。

### 3.3 筛选维度

筛选条件之间为“且”关系，控件与默认值由 metadata 生成：

- 办学性质：全部、公办、民办。
- 招生类别：普通计划、建档立卡专项、全部；为延续现状，默认普通计划。
- 公共课：全部、公共英语、专业英语。
- 专业基础课：metadata 中的实际枚举，包括高等数学、管理学、大学语文、经济学、法学基础和各类专业综合等。
- 省控线：目标年份 + 最低分 + 最高分；快捷档位为 `80–100`、`101–150`、`151–200`、`201+`，具体值保存在 metadata。
- 院校数量：目标年份 + 最低院校数；比较规则由 metadata 指定为 `>=`，不再在代码中硬编码 2026 或“大于”。

无对应年份省控线的专业在启用分数区间时不匹配；未启用分数区间时仍保留。

### 3.4 年份多选与结果布局

年份不是写死的下拉框。聚合结果区右上角的“年份”按钮打开原生 `<dialog>` 弹窗，弹窗从 `metadata.supportedYears` 动态生成复选框，并按 metadata 的年份排序显示。默认勾选全部支持年份，以保留跨年对照；新增年度后无需修改页面代码即可出现。

- 弹窗提供“全选”“仅最新年份”“取消”“应用”操作。应用时至少保留一个年份；试图提交空选择时保留原选择并给出就地提示。
- `selectedYears` 是结果、筛选、预览和导出的统一年份集合，不是仅改变可见列的装饰状态。年份从集合移除后，不参与筛选、聚合、表格列或 CSV 列。
- `focusYear` 取已勾选年份中最新的一个，作为当前专业对照/搜索索引的查询基准年。仅勾选 2024 时必须使用 2024 的专业对照，不能继续使用 `defaultYear` 的映射；勾选多个年份时使用其中最新年份。切换集合后必须同步调用查询映射切换逻辑。
- 带年份含义的筛选（省控线区间、院校数、公办/民办、普通/建档立卡和计划人数）在每个已勾选年份独立判断；某本科专业只要在任一已勾选年份满足全部已启用的年份筛选即可保留。非年份筛选仍对专业自身元数据判断。结果卡片、表格和导出必须明确仅包含勾选年份，避免把“任一年命中”误读为“每年命中”。

“布局”按钮在“聚合卡片”和“表格”之间切换。两种布局只消费同一个已筛选、已排序的 `MajorAggregate[]` 和投影器，禁止各自再做一次筛选或排序。结果视图使用独立的显式详情状态，以专业索引作为键；它只影响局部详情渲染，不触发 explorer 全局重算：

- **聚合卡片：** 保留专业摘要与逐年摘要；展开一次后按学校身份分组，卡内按年份展示完整招生计划记录，只渲染 `selectedYears`。
- **表格：** 每个本科专业一行，表头固定为专业、科目、历年概览和院校对比；年份数据放在行内，避免 2025/2026 等动态年份占用表头。结果表容器可横向/纵向滚动，表头 sticky；行内可进入同一份院校对比明细。
- 布局仅是 UI 偏好，可以保存；年份选择会保存为 UI 偏好，但从不把查询结果、业务原始数据或聚合数据写入 localStorage。

### 3.5 本科专业聚合结果

每个本科专业的首层摘要展示：

- 本科专业名称、填报代号、六位专业代码。
- 公共课：公共英语或专业英语。
- 专业基础课与考试科目代码。
- 已勾选年份的省控线及相邻已选年份变化。
- 当前/最新年份招生摘要。

展开专业后按已勾选年份显示，每个年份固定展示两组：

- `公办 X 所 · 普通 Y 人 · 建档立卡 Z 人`
- `民办 X 所 · 普通 Y 人 · 建档立卡 Z 人`

院校数按规范化院校身份去重。普通计划和建档立卡计划使用不同院校代号时，仍通过规范化学校名称合并为同一院校；院校内部再分别显示普通计划人数和建档立卡人数。这样既能聚合阅读，也不会把两种招生类别混成一个不可解释的总数。

展开院校后保留全部现有明细：院校代码、专业代号、学制、普通计划、建档立卡计划、学费、最低住宿费、办学性质、招生类别、通信地址、其他说明、咨询电话、招生章程网址，以及回退数据中的师范/艺术标记。

### 3.6 一分一段聚合

每个本科专业按年份显示官方一分一段数据。默认摘要包括省控线、该省控线对应的累计人数，以及用户输入分数对应的累计人数和高出省控线的分差。展开后才加载或渲染完整分数段，避免把三年全部明细一次性放入 DOM。

官方表中的“考生人数”按官方口径保存为 `cumulativeCount`。如界面需要展示“本分数人数”，只能由相邻累计值计算，并标记为推导值；不得反写原始数据。相同分数可能对应多人，因此累计人数只作为参考位次，不能承诺唯一名次。

### 3.7 预览与导出

默认预览列由 metadata 生成，包括：

- 本科专业、填报代号、公共课、专业基础课、考试科目代码。
- 每个已勾选年份的省控线。
- 每个已勾选年份的院校数（公/民）。
- 每个已勾选年份的普通计划人数（公/民）。
- 每个已勾选年份的建档立卡计划人数（公/民）。

年份列由字段模板按 `selectedYears` 展开，候选年份来自 `supportedYears`；新增 2027 时不再手写 `score2027`、`planSplit2027` 等业务代码。预览表格与 CSV 共同使用完整的筛选排序投影结果，而不是当前分页 DOM；布局切换不会改变该结果。文件名为 `院校数据_<focusYear>_<YYYYMMDD>.csv`。

## 4. 数据与 metadata 设计

### 4.1 数据目录与迁移

`data/` 按数据类型分目录，目录内文件按年份命名，不以年份作为顶层目录：

```text
data/
  专业对照/
    原始PDF/
    专业对照_2026.json
  省控线/
    原始PDF/省控线_2024.pdf ...
    省控线_2024.json ...
  招生计划/
    原始PDF/招生计划_2024.pdf ...
    招生计划_2024.json ...
  招生高校及专业/
    原始PDF/
    招生高校及专业_2026.json
  一分一段/
    原始PDF/2024/ ...
    原始PDF/2025/ ...
    原始PDF/2026/ ...
    一分一段_2024.json
    一分一段_2025.json
    一分一段_2026.json
  来源清单/
    来源清单_2024.json ...
  schemas/
  reports/
  README.md
crawler/
convert/
```

一分一段每年包含多份按专业发布的 PDF，因此其原始文件在数据类型目录内再按年份分组；规范化 JSON 仍按年份命名。现有 `pdf/` 与 `data/` 根目录文件使用 `git mv` 迁移，以保留文件历史并让 Git 正确识别重命名。后续修改不得通过删除后重建绕过迁移历史。

`crawler/` 只保存来源发现与下载工具，`convert/` 只保存 PDF 抽取、归一化和校验工具；原始文件与产物均属于 `data/`。Python 依赖分别记录，批处理入口必须支持全量运行和指定年份重跑。

### 4.2 官方来源优先级与冲突处理

重复字段不以“最后读取的文件”为准，而按官方文件职责确定权威来源：

- 专业代码、专业名称、考试科目以官方专业对照表为准。
- 省控线以官方招生录取控制分数线为准。
- 院校、招生专业、计划人数、学费等以官方招生计划表为准。
- 分数与累计人数以官方一分一段表为准。
- 招生高校及专业总表只补齐招生计划表未提供的字段，不覆盖已有权威值。

多份官方文件对同一权威字段产生冲突时，转换不得静默覆盖或自动猜测。规范化结果采用上述优先级对应的值，同时在年度转换报告中记录数据键、各来源原值、采用值、采用依据和源文件。没有明确优先级的冲突作为转换失败处理，必须人工确认后才能发布该年度产物。

### 4.3 一分一段采集与转换

采集流程固定为：发现官方年度页面 → 生成来源清单 → 批量下载 → 计算 SHA-256 → `pdfplumber` 批量抽取 → 归一化 → Schema/业务校验 → 输出年度 JSON 与报告。下载器支持重复运行、跳过哈希一致文件、失败重试和失败清单；不得依赖浏览器运行时联网。

年度一分一段文件使用统一结构：

```json
{
  "year": 2026,
  "majors": [
    {
      "majorCode": "73",
      "majorName": "高分子材料与工程",
      "sourceId": "2026-score-segment-73",
      "segments": [
        { "score": 220, "cumulativeCount": 3 }
      ]
    }
  ]
}
```

来源清单至少保存年度、来源页面、PDF URL、本地相对路径、专业代码、专业名称、下载时间、SHA-256、HTTP 状态和转换状态。校验覆盖专业代码唯一、专业名称与权威对照表一致、分数严格降序、同专业分数不重复、累计人数随分数下降单调不减，以及来源清单与本地文件一一对应。PDF 版式无法可靠解析时写入异常报告，不输出貌似完整的错误记录。

### 4.4 metadata v2

在保持 JSON 配置独立的前提下，把当前逐年硬编码字段改为以下概念：

- `supportedYears`、`defaultYear`、`yearSources`：每年数据源。
- `scoreSegmentSource`：每年规范化一分一段数据源。
- `queryIndexSource`：轻量专科专业索引；缺失时允许回退到 mappingSource。
- `sourceFields`：原始中文字段到规范字段的映射。
- `derivedFields.publicCourse`：专业英语判定规则、默认公共课与显示标签。
- `fields`：非年度字段配置。
- `yearFieldTemplates`：省控线、院校数、普通计划、建档立卡计划模板。
- `filters`：目标字段、控件类型、默认值、枚举、范围、比较符与适用年份。
- `defaultSort`、`scorePresets`、`pageSize`、`exportFormat`。
- `uiDefaults`：默认结果布局和默认年份选择策略；默认策略为 `allSupportedYears`，实际可选年份始终以 `supportedYears` 为准。

metadata 加载时验证版本、年份引用、源路径、字段 key 唯一性、筛选/排序字段可解析性、默认值合法性和模板展开后 key 不冲突。数据文件继续由 JSON Schema 在测试中做完整校验，浏览器加载边界执行轻量结构校验并给出文件名、年份和错误字段。

### 4.5 规范化领域模型

业务逻辑只消费以下规范对象，不直接读取中文源字段：

```text
MajorOption
  majorId, majorName, majorCode, disciplineCode6
  publicCourse
  professionalCourse { code, name }

PlanEntry
  year, schoolId, schoolName, schoolType
```

`schoolId` 优先使用规范化学校名称作为跨普通/专项记录的稳定聚合键，原始院校代号保留在明细中。严禁仅用院校代号合并，因为同一学校的建档立卡条目可能采用不同代码。

## 5. 加载与渲染性能

### 5.1 加载阶段

1. 首屏只加载 HTML/CSS、metadata 和轻量 `queryIndexSource`，搜索框尽快可用。
2. 用户确认专业后加载 `focusYear` 的 mappingSource、`focusYear` 省控线和计划；相同 URL 只请求一次。
3. 浏览器空闲时预取其他年份的小型省控线文件，不预取大型招生计划。
4. 展开任一已选年份、打开完整预览或导出时才加载对应计划文件；取消勾选不会清除已在内存中的可复用缓存。
5. 所有已加载数据只缓存在内存 Map；localStorage 不保存原始数据、索引、聚合结果或筛选结果。

### 5.2 渲染阶段

- 主结果先渲染本科专业摘要，年份和院校明细在展开时生成 DOM。
- 统一事件委托，避免每行重复绑定监听器。
- 预览分页渲染，默认每页 50 行；列宽只保存数值型 UI 偏好。
- 筛选输入使用一次微任务/动画帧合并更新，避免同一事件触发多次完整计算。
- ECharts 从首屏同步脚本移除，进入数据分析页签时动态加载；加载失败继续显示已有表格降级。

## 6. 状态、异常与存储

- 加载状态至少区分：metadata、搜索索引、`focusYear`、其他已选年份和导出准备。
- 单个历史年份加载失败时保留当前年份结果，并在该年份区域显示重试按钮。
- metadata 或默认年份核心数据失败时显示整页友好错误，但不白屏。
- 查询无匹配、筛选无结果、年份无计划、年份无省控线分别使用不同文案。
- 清除本地存储：清空全部 localStorage、恢复主题自动模式、清空筛选和排序、恢复布局、年份选择、列宽与分页；随后用当前已在内存的数据重新渲染，不重复下载。
- localStorage 只允许保存主题、筛选/排序 UI 状态、年份选择、结果布局、分页大小和列宽。

## 7. 非目标与后续扩展

本轮不实现：用户账号、云同步、后端数据库、院校实际录取线、退役士兵考查、志愿推荐算法。爬虫仅用于采集河南省教育考试院公开的 2024–2026 官方文件，不建设通用采集平台，也不把非官方聚合站作为业务数据来源。

## 8. 验收标准

1. 搜索“软件技术”等非完整输入后回车，输入框与结果上下文显示最终采用的完整专科专业名。
2. 每个本科专业同时展示公共课、专业基础课及代码，专业基础课可筛选。
3. 公办/民办、普通/建档立卡筛选按“且”生效；“全部”时仍分别显示普通和专项人数。
4. 同一学校普通与专项使用不同院校代码时，年份院校数只计一次，人数分别保留。
5. 省控线范围支持手输和快捷档位，非法字符、负数和最小值大于最大值被阻止或提示。
6. 预览列、顺序和值与 CSV 完全一致；分页不影响导出完整结果。
7. 年份弹窗从 metadata 动态生成、至少保留一个勾选项；只勾选旧年份时，专业搜索索引随之切换到该年份。
8. 聚合卡片与表格布局展示同一行集、同一顺序和同一已选年份集合；切换布局不改变 CSV 内容。
9. 首屏不请求任何招生计划文件和 ECharts；历史计划只在实际需要时请求，重复操作命中内存缓存。
10. 新增 2027 只添加/替换数据文件并修改 metadata，现有业务模块和 UI 代码不改动。
11. metadata、数据源或单一年份加载失败均有可理解的错误状态，不出现白屏。
12. `npm test` 全部通过，并增加年份多选、查询映射切换、两布局等价、懒加载、模板年份和导出一致性测试。
13. 现有 PDF 和 JSON 通过 `git mv` 迁入按数据类型组织的目录，Git 能识别主要文件为重命名而非无关删除与新增。
14. 2024–2026 一分一段 PDF 均有来源清单、SHA-256、转换状态和年度规范化 JSON；下载或解析失败项在报告中完整列出。
15. 转换工具可全量运行，也可只重跑一个年份；同一输入重复运行生成字节稳定的规范化 JSON。
16. 重复字段遵循官方文件职责优先级，所有冲突均进入报告，不发生静默覆盖。
